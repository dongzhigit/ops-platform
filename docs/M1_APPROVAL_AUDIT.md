# M1 高风险操作审批与审计

本阶段增加统一的 `audit` 应用，为高风险运维操作提供双人审批、一次性批准票据、关联 ID 和防篡改审计链。当前已接入批量命令、SFTP 上传/删除、文件分发、计划任务，并将原有发布审批事件写入统一审计链。

## 安全规则

- 风险等级由服务端根据动作、命令特征和目标数量计算，客户端不能指定或降低风险。
- `high` 和 `critical` 操作必须审批；严重风险申请必须提供回滚方案。
- 申请人与审批人不能是同一用户，当前审批人必须是系统管理员。
- 审批绑定动作、目标集合和结构化参数的 SHA-256，任何参数或目标变化都会失败关闭。
- 批准后默认 30 分钟内可消费，最长 120 分钟；批准票据只能消费一次。
- 执行入口和异步 Worker 都会重新检查对象授权及审批记录。
- 凭据、密码、私钥、Cookie 和 Token 等字段写入审计前会被脱敏。

风险示例：

| 操作 | 默认风险 |
| --- | --- |
| 普通批量只读命令 | 中 |
| 包含 `sudo`、服务重启、软件安装等命令 | 高 |
| `rm -rf`、磁盘格式化、重启关机等命令 | 严重 |
| 文件上传、文件分发、计划任务配置/启用 | 高 |
| 文件删除、发布执行 | 严重 |
| 10 台及以上目标 | 至少高 |
| 50 台及以上目标 | 严重 |

## API 流程

新增接口统一位于 `/api/v1/audit/`：

- `POST preview/`：由服务端预判风险并返回与当前动作、目标和参数完全匹配的有效审批单。
- `GET/POST/DELETE approvals/`：查看、创建或撤销审批单。
- `PATCH approvals/<uuid>/decision/`：管理员批准或驳回。
- `GET events/`：管理员查看审计事件，可按 `correlation_id`、动作和结果过滤。
- `GET verify/`：验证审计链。

以高风险批量命令为例，申请时的 `payload` 必须和实际执行请求保持一致：

```json
{
  "action": "exec.run",
  "resource_type": "host",
  "resource_ids": [1, 2],
  "summary": "滚动重启 nginx",
  "rollback_plan": "恢复上一版配置并重新启动 nginx",
  "payload": {
    "host_ids": [1, 2],
    "command": "sudo systemctl restart nginx",
    "interpreter": "sh",
    "template_id": null,
    "params": {}
  }
}
```

另一名管理员批准：

```json
{
  "is_pass": true,
  "comment": "已确认变更窗口和回滚方案",
  "ttl_minutes": 30
}
```

执行时在原请求中增加：

```json
{
  "approval_id": "审批单 UUID"
}
```

SSH 文件上传先以 JSON 元数据创建持久化上传会话并传递 `approval_id`，批准票据只在创建会话时消费；后续分片以会话 UUID、精确偏移和分片摘要授权。文件删除通过查询参数传递审批单。文件分发的审批参数包含目标目录、源主机/路径或待上传文件名与大小。计划任务的“配置变更”和“启用/手动执行”使用不同审批单，避免批准配置等价于永久批准执行。

## 管理页面

“安全中心”提供以下页面：

- **我的申请**：所有登录用户可查看和筛选自己的审批申请，并撤销尚未处理的申请。
- **待我审批**：系统管理员可批准或驳回申请、填写审批意见并设置 1 至 120 分钟的票据有效期；申请人不能审批自己的申请。
- **审计日志**：系统管理员可按关联 ID、动作和结果过滤事件，并在线验证 HMAC 审计链完整性。

批量命令、文件分发、SSH 文件上传/删除以及计划任务的创建/编辑、启用、手动测试和删除页面使用统一审批门禁。浏览器只提交结构化操作参数，风险分级、参数哈希和有效票据匹配均由服务端完成。若尚无票据，页面创建申请但不执行；另一名管理员批准后，申请人重新发起原操作即可选择匹配票据执行。SSH 文件上传在票据匹配并消费前只在本地分片计算摘要，不会发送文件内容；上传会话和校验流程见 [M2 SFTP 分片上传与断点续传](M2_RESUMABLE_SFTP.md)。删除操作必须提供回滚方案。

## 审计完整性

生产环境必须设置独立的 `SPUG_AUDIT_SIGNING_KEY`，不能和 Django Secret 或凭据主密钥复用。每条事件包含全局递增序号、前置哈希及 HMAC-SHA256 签名，应用层禁止更新和删除审计事件。

可执行以下命令进行完整性检查：

```bash
python3 manage.py verify_audit_chain
```

当前实现属于“可检测篡改”的数据库审计链。具备数据库管理权限并同时取得签名密钥的攻击者仍可能重写记录；正式合规环境后续需要把事件副本投递到独立日志平台或 WORM 对象存储。

## 当前限制

- SSH 文件管理已实现单文件分片上传与续传、校验、单段 HTTP Range 断点下载和过期临时文件自动清理；批量队列、可选冲突交互与在线编辑仍未实现。
- 发布模块仍使用原有发布申请审批模型，本阶段只完成双人限制和统一审计事件桥接；未启用发布审核的应用仍沿用旧行为。
- SSH 终端会话录像、逐命令记录和完整执行证据尚未实现。
- 审批通知、审批组和多级审批链尚未实现。
