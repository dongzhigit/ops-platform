# M6 AI 拓扑诊断与事件作战室

版本：`0.1.0-alpha.43`
记录日期：2026-09-07

## 目标

建设一套面向故障定位的 AI 拓扑诊断能力。系统应清晰展示服务器、应用、服务、端口、监控指标、告警事件和调用关系，并允许运维人员围绕某个异常节点发起只读 AI 调查，快速判断问题可能出在哪一层、影响哪些服务、下一步应该检查什么。

该能力不是让 AI 直接执行命令。第一阶段仍保持只读，所有结论必须来自授权资产、监控、告警、运行态快照、知识库或人工录入的依赖关系。

## 用途

- 从主机、服务、端口、应用和告警之间的关系定位业务故障点。
- 在拓扑图上直观看到链路状态，例如正常、未知、降级、严重。
- 从告警直接跳转到受影响节点、上下游依赖和 AI 调查记录。
- 将 AI 诊断结果沉淀为知识库文档、Runbook 或故障复盘草稿。
- 为后续受控自动化修复提供证据链、审批入口和验证基础。

## 阶段计划

### P0：需求固化与数据模型

状态：已完成基础模型与只读接口

交付内容：
- 定义拓扑对象类型：服务器、应用、服务、监听端口、数据库、中间件、外部接口、监控目标。
- 定义拓扑边类型：部署于、监听、调用、依赖、采集、告警关联、发布关联。
- 定义节点状态来源优先级：告警事件、Prometheus 指标、探测状态、运行态快照、人工维护状态。
- 定义最小权限规则：用户只能看到自己有权访问的资产、服务和证据。

验收标准：
- 产出后端模型和接口设计。
- 产出前端拓扑页面字段清单。
- 明确哪些数据来自自动发现，哪些必须人工维护。

前端拓扑页面字段清单：
- 节点：ID、唯一标识、类型、名称、描述、来源类型、来源对象 ID、健康状态、状态来源、扩展属性、坐标、是否启用。
- 连线：ID、源节点、目标节点、关系类型、标签、健康状态、状态来源、是否已探测、扩展属性、是否启用。
- 图谱元数据：节点类型枚举、关系类型枚举、状态枚举、状态来源枚举、状态来源优先级、权限策略说明。

数据来源边界：
- 自动发现：主机资产、应用配置、服务配置、监控采集目标、Prometheus/Alertmanager 状态、后续运行态快照。
- 人工维护：外部接口、临时依赖、跨系统调用关系、无法从配置或监控稳定推断的业务关系。
- 默认状态：未采集到监控或告警证据时必须为 `unknown`，不得默认标记为 `critical`。

### P1：静态拓扑与手工关系维护

状态：已完成静态拓扑维护和图谱页面

交付内容：
- 新增拓扑节点和连接关系的后端接口。
- 支持在页面中创建、编辑、删除服务器、服务、应用和连接关系。
- 拓扑视图展示节点、连线、方向、分组和基础状态。
- 支持从已有主机、应用、服务配置中选择对象，避免重复录入。

验收标准：
- 能手工建立 `服务器 -> 服务 -> 应用` 的基础拓扑。
- 拓扑图能稳定展示连线，节点拖拽或布局不会丢失关系。
- 无权限资产不会出现在拓扑图或接口响应中。

### P2：监控和告警状态联动

状态：已完成监控和告警状态联动

交付内容：
- 将 Prometheus target、Alertmanager 告警、主机指标和服务状态映射到拓扑节点。
- 节点和连线显示健康状态、告警数量、最近采集时间和数据来源。
- 支持按环境、主机组、应用、严重级别过滤拓扑。
- 从拓扑节点跳转到监控面板、告警详情、主机详情和远程入口。

验收标准：
- 已接入监控的服务器能自动显示采集在线或离线。
- 告警恢复后拓扑状态能回落。
- 未采集到证据的节点显示未知，而不是默认严重。

### P3：AI 拓扑诊断

状态：已完成只读拓扑诊断闭环

交付内容：
- 允许从拓扑节点、连线、告警或选中范围发起 AI 只读调查。
- AI 证据包含拓扑邻接关系、节点状态、指标摘要、告警、运行态服务快照和知识库片段。
- 输出影响范围、可能故障点、证据引用、未知项、建议检查步骤和人工行动方案。
- 调查结果回写到事件记录，并可关联知识库或复盘。

验收标准：
- AI 结论必须引用当前证据集合。
- 无证据时必须说明未知，不得编造服务关系或运行状态。
- 大模型不可接触凭据、任意 Shell、数据库写入或审批票据。

实现记录：
- 拓扑图可从选中节点发起 AI 只读诊断，并自动扩展相邻节点和连线作为拓扑范围。
- AI 证据包新增 topology 类型，包含可见节点、连线、状态来源、指标摘要、告警数量和关联主机 ID。
- 拓扑范围内解析出的主机会继续采集授权资产、Prometheus 指标、告警、运行态服务快照和知识库证据。
- 模型输出新增影响范围和可能故障点字段，仍必须通过引用校验和禁止可执行字段校验。

### P4：事件作战室

状态：已完成事件作战室最小闭环

交付内容：
- 以告警或故障为入口聚合拓扑、指标、日志摘要、变更记录、Runbook、AI 调查和负责人。
- 支持事件时间线、人工备注、认领、升级和复盘草稿。
- 支持把有效排障步骤保存为 Runbook 草稿。

验收标准：
- 单个事件可以串联告警、拓扑节点、AI 调查、人工操作和复盘。
- 普通用户只能看到自己有权访问的资产和证据。
- AI 不可自动关闭事件或修改生产配置。

实现记录：
- 新增事件作战室模型和接口，支持关联告警、拓扑节点和 AI 调查记录。
- 支持事件认领、状态变更、人工备注时间线和复盘草稿保存。
- 事件详情可聚合展示关联告警、拓扑范围、AI 调查和人工时间线。
- 普通用户仅可访问自己创建、自己负责或具备关联告警主机指标权限的事件。

### P5：受控修复建议与审批闭环

状态：已完成受控修复提案与审批最小闭环

交付内容：
- AI 只生成结构化修复建议，不直接执行。
- 建议可以转换为待审批的白名单动作，例如重启受控服务、扩容建议、切换流量检查项。
- 执行必须经过权限校验、风险分级、人工审批、灰度、验证和回滚。

验收标准：
- 无审批不能执行写操作。
- 所有执行具备证据、审批、命令、输出、验证和回滚记录。
- 提示注入和越权测试必须通过。

实现记录：
- 新增 AI 修复提案模型和接口，支持把 AI 行动方案转换为人工可编辑的受控修复提案。
- 修复提案仅允许白名单动作类型，例如人工检查、受控服务重启评审、容量扩容评审、流量切换评审、发布回滚评审和配置变更评审。
- 提案提交后会创建 `aiops.remediation.propose` 审批单，并记录审计事件、风险等级、目标引用、证据引用、验证方案和回滚方案。
- 审批通过不会自动执行命令或变更；后续真实写操作仍必须另行进入平台已有授权、审批消费、执行、验证和回滚记录流程。
- 后端会拒绝提案字段中的 `command/cmd/shell/tool` 类可执行字段和明显命令文本，严重风险提案必须填写回滚方案。

### P6：审批后执行证据与验证回滚记录

状态：已完成执行证据登记最小闭环

交付内容：
- 审批通过的修复提案可以登记执行证据，支持人工执行记录和平台执行引用两种模式。
- 执行记录包含平台动作引用、执行引用号、执行摘要、验证结果、回滚结果和状态流转。
- 执行登记不调用 SSH、发布、配置写入或流量切换接口；真实写操作仍必须由对应业务模块独立授权、审批消费和审计。

验收标准：
- 未审批通过的修复提案不能登记执行。
- 执行完成或失败必须记录验证结果；回滚必须记录回滚结果。
- 执行摘要、验证结果和回滚结果不得包含明显命令文本、工具调用字段或密钥类内容。

实现记录：
- 新增 AI 修复执行记录模型和接口，支持 `running -> succeeded/failed/rolled_back` 状态流转。
- 修复提案详情会聚合展示关联执行记录，方便从 AI 调查中追踪建议、审批、执行登记、验证和回滚结果。
- 提案状态会随执行记录同步为执行登记中、已验证成功、验证失败或已回滚，且不会被审批单状态覆盖回退。

### P7：平台操作记录引用校验

状态：已完成平台执行记录只读校验

交付内容：
- 支持在审批通过后的执行登记中选择可访问的平台操作记录作为执行证据。
- 已接入批量执行、文件分发、发布执行、计划任务和配置变更历史的只读引用查询。
- 登记平台引用时按当前用户权限校验记录可见性，不允许引用不可见或不存在的执行记录。
- 返回给前端的引用摘要只包含记录 ID、类型、状态、时间、操作者等元数据，不包含命令正文、输出、参数、配置值或密钥。

验收标准：
- 平台引用模式必须同时选择平台动作和执行引用。
- 不存在、越权或暂未接入可验证模型的动作会被拒绝。
- 审计事件只记录平台动作、引用号、记录类型和记录 ID，不记录敏感 payload。

实现记录：
- 新增 `/api/v1/aiops/remediations/platform-references/` 接口，用于按平台动作列出当前用户可访问的执行记录。
- `AIRemediationExecution` 新增 `platform_record` 字段，持久化脱敏后的平台记录摘要。
- 后端创建执行登记时会再次按权限和真实记录校验引用，前端选择框只展示已接入且可校验的动作。

### P8：事件作战室修复闭环展示

状态：已完成事件闭环展示

交付内容：

- 事件详情不展示命令正文、配置密文、执行输出或密钥类内容。
- 修复提案与 AI 调查或事件房间任一关联时，都能在事件详情中被聚合展示。

- M6 应用层阶段 P0-P8 已形成闭环；真实变更执行仍保持在各业务模块已有授权、审批消费、执行和审计流程内。

### P9：运行态进程拓扑扫描

状态：已完成运行态进程、监听端口和连接关系扫描

交付内容：
- 在拓扑页提供“扫描运行态”入口，可选择有权限的主机进行只读扫描。
- 扫描主机进程、监听端口和 TCP 已建立连接，并生成运行态拓扑节点和连线。
- 自动生成 `主机 -> 进程 -> 监听端口` 以及 `进程 -> 连接对端` 的关系，跨主机已知监听端口会直接连到对应端口节点。
- 连线状态使用现有颜色体系展示，已建立/监听连接标记为正常，无法确认的远端节点保持未知。

验收标准：
- 扫描必须使用固定只读采集命令，不接收模型生成命令或用户自定义 Shell。
- 需要拓扑管理权限、主机查看权限和目标主机 SSH 连接权限。
- 运行态节点按主机权限过滤，无权用户不能看到对应主机的进程、端口和连接。
- 不采集命令行参数、执行输出、环境变量、配置密文、密钥或 token。

实现记录：
- 新增 `/api/v1/topology/runtime-scan/` 接口，单次最多扫描 10 台主机。
- 拓扑节点类型新增 `process`，运行态节点统一写入 `source_type=runtime` 和精确 `source_id=host_id`。
- 每次扫描会停用该主机上一轮自动发现的运行态节点和本主机发出的运行态边，再写入本轮扫描结果。
- 拓扑页新增运行态详情区，展示采集时间、进程名、PID、协议、端口和连接对端等脱敏元数据。

### P10：分层拓扑视图

状态：已完成服务器链路总览、服务链路钻取和完整视图切换

交付内容：
- 拓扑页默认进入服务器链路视图，只展示服务器资产以及服务器之间聚合后的业务调用关系。
- 在服务器链路视图点击主机节点后进入服务链路视图，只展示该主机内的进程、监听服务和相关对端服务连接。
- 保留完整视图用于深度排查全部节点和连线。
- 工具栏显示当前画布节点和连线数量，帮助判断当前视图是否有可见连接数据。

验收标准：
- 默认视图不展示进程、端口、MySQL、Redis 等服务节点，避免误读成“服务器连接了哪些服务”。
- 服务链路视图优先展示服务到服务的连接，只有无法识别具体服务时才显示主机或外部端点作为兜底上下文。
- 完整视图仍能看到原始运行态节点和连线。
- 状态颜色、权限过滤和 AI 只读证据边界保持不变。

### P11：运行态业务全链路识别

状态：已完成前端、后端、数据库和中间件业务连接识别，已补充 Django 等框架脱敏指纹识别

交付内容：
- 运行态扫描保留 Nginx/Vue/Node 前端、Python/Go/Java/Node 后端、数据库和中间件之间的业务连接。
- 继续过滤随机客户端端口、SSH、监控 exporter、Prometheus、Alertmanager 等非业务连接，避免主图噪声过多。
- 节点元数据记录 `runtime_layer` 和 `connection_kind`，用于区分 frontend、backend、database、middleware 以及 dependency/application 连接。
- 新增主机验证成功后可自动触发只读业务拓扑发现，生成默认拓扑后仍允许人工确认和补充。
- 对 Python/Gunicorn/uWSGI/Uvicorn/Daphne 等进程增加脱敏框架指纹，远端只返回 `PID -> django` 等标签，不返回完整命令行参数。
- 所有监听端口都会进入候选服务列表；无法识别的端口显示为 `TCP Service` 且默认不勾选，由运维人员人工确认。
- 业务连接保存时优先保留具体来源进程，只有无法确认 PID 时才回退到主机或端口节点。
- 目标主机支持免密 `sudo -n` 时，运行态扫描会自动使用 sudo 读取 netstat/ps 的 PID 与进程名，仍只保存脱敏后的进程名和框架标签。
- 对 `mysqld`、`redis-server` 等数据库/中间件进程增加服务画像，非标准端口也能按进程识别为 MySQL、Redis 等服务。
- Django 进程没有实时数据库连接时，运行态扫描会读取 settings/config/.env 中不含密码的 ENGINE/HOST/PORT 线索，生成配置发现的固定数据库依赖，保存后的健康状态仍由运行态连接或端口探测确认。
- 非标准端口识别优先使用监听进程归属，避免 Redis/MySQL 这类服务因端口落在后端范围内被误判为 Backend API；公网或未纳管客户端访问不会默认写入固定业务拓扑。
- Nginx upstream/proxy 配置会作为脱敏应用链路证据参与拓扑生成，使 `Nginx -> Django -> MySQL/Redis` 能在没有瞬时长连接时仍保持串联；内网客户端访问共享 MySQL/Redis 会汇聚到对应依赖节点。

验收标准：
- 可以展示 `前端 -> 后端 API -> MySQL/Redis` 等业务链路。
- Python 启动的 Django 项目应显示为 Django 后端服务，而不是被泛化成普通 python 进程或遗漏。
- 未命中内置服务规则的监听端口仍可在候选列表中看到，避免自定义端口服务被漏扫。
- Django/Python 进程连接 MySQL/Redis 时，拓扑连线来源应指向该进程节点，而不是被强制聚合成主机节点。
- 普通 netstat 无法看到 PID、但 `sudo -n netstat` 可看到 PID 时，应能生成具体进程到数据库/中间件的连接。
- MySQL 监听在 `13306` 等非标准端口时，只要能看到 `mysqld` 进程，应识别为 MySQL。
- Django settings 中存在 MySQL/PostgreSQL HOST/PORT 时，即使扫描瞬间没有 ESTABLISHED socket，也应给出可人工确认的业务依赖连接。
- `redis-server` 监听 `7008` 等非标准端口时，Python 进程连接该端口应显示为 Redis 依赖，而不是 Backend API。
- 未纳管外部客户端访问 Django/Nginx 等入口端口不应默认成为固定业务依赖线。
- Nginx 配置中存在 `proxy_pass`、`uwsgi_pass`、`fastcgi_pass` 或 upstream `server host:port` 时，应生成 Nginx 到对应本机或已纳管后端服务的业务连接。
- 内网系统连接共享 MySQL/Redis 时，即使该系统暂未纳管，也应以外部系统节点汇聚到该数据库/中间件服务。
- 随机浏览器回连、临时高端口连接和系统采集进程不进入默认业务拓扑。
- 新增主机时的自动发现不保存密码、密钥、命令行参数、环境变量或配置密文。
- AI 仍只基于已授权证据做诊断，不直接执行命令或自动变更拓扑确认结果。

### P12：主机接入拓扑发现确认

状态：已完成新增主机后的发现预览和人工确认入口

交付内容：
- 运行态扫描接口支持 `dry_run` 预览模式，只返回候选服务和候选连接，不写入拓扑数据库。
- 新增主机验证成功后先执行只读业务拓扑发现，展示默认选择的服务、层级、进程和业务连接。
- 运维人员点击确认后才生成拓扑；取消时不修改现有拓扑。
- 预览和正式生成共用同一套业务链路识别规则，避免确认结果和最终落库结果不一致。

验收标准：
- 新增主机后能够看到自动发现候选项，再决定是否生成拓扑。
- 未发现候选服务或业务连接时不写空拓扑，只提示未发现可自动生成的业务拓扑。
- 预览模式不停用旧运行态节点和连线。
- 确认生成仍受拓扑管理权限和 SSH 连接权限控制。

### P13：对端服务解析与链路标签增强

状态：已完成已扫描对端主机的服务解析和显示增强

交付内容：
- 调用连接的目标如果是已扫描主机上的监听端口，连线会直接指向对端运行态服务节点。
- 监听端口节点名称增加服务信息，例如 `Redis 6379/tcp`、`java backend 8080/tcp`，不再只显示端口号。
- 调用线标签增加目标服务信息，例如 `MySQL TCP 192.168.18.55:3306`、`java backend TCP 192.168.18.227:8080`。
- 服务器视图聚合多条连接时保留首个服务标签，避免只显示“几条连接”而看不到连接的服务类型。

验收标准：
- 发起端和对端都扫描过时，可以看到“哪个程序连接到对端哪个服务”。
- 对端未扫描时，仍按端口规则显示 MySQL、Redis、Backend API 等可推断服务。
- 不因为增强显示而放开随机高端口、SSH、监控 exporter 等噪声连接。

### P14：运行态依赖连接双向归一化

状态：已完成 tcp6/udp6 解析、服务端方向连接识别和服务器总览关键服务展示

交付内容：
- 运行态 socket 解析支持 `tcp6`/`udp6`，统一归一为 TCP/UDP 协议，避免 MySQL/Redis 等服务只监听在 IPv6 socket 时被漏掉。
- 当连接的本机端口是 MySQL、Redis、PostgreSQL、MongoDB、RabbitMQ、Kafka 等数据库/中间件端口时，拓扑会识别为“客户端/来源主机 -> 本机服务”的入站业务连接。
- 服务器级拓扑会聚合展示关键数据库/中间件监听服务，即使当前没有可确认的调用边，也能看到主机上正在提供的 MySQL/Redis 服务。

验收标准：
- `tcp6 :::3306` 监听能生成 MySQL 运行态服务节点。
- `192.168.18.244:6379 <- 其他主机高端口` 能生成指向 Redis 服务的调用边。
- 仍然过滤随机客户端高端口、SSH、exporter 和非业务连接噪声。

### P15：固定业务服务拓扑监控

状态：已完成候选发现与固定监控分离

交付内容：
- 运行态扫描默认只发现候选服务和候选业务连接；只有运维人员确认勾选后，才写入长期拓扑监控。
- 确认后的服务端口和业务依赖会写入 `monitor_mode=fixed`，后续扫描保留这些固定项，只更新监听状态、连接状态和最近检查结果。
- 拓扑页和新增主机页都提供候选确认入口，未勾选的临时连接不会进入长期监控拓扑。
- 固定业务依赖保存探测源主机、目标地址和目标端口，为“应用连接 MySQL/Redis 是否正常”这类服务端口连通性判断提供基础。

验收标准：
- 自动扫描不会直接把所有临时 TCP 连接写入拓扑。
- 已确认的 MySQL、Redis 等服务端口长期保留，服务消失时状态可以刷新为离线。
- 已确认的业务依赖长期保留，后续扫描只刷新连通状态，不自动新增未确认连接。
