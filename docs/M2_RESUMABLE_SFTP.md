# M2 SFTP 分片上传、批量队列、断点下载与在线编辑

`0.1.0-alpha.8` 在受审批的 SFTP 分片上传、批量队列、Range 下载和临时文件清理基础上，增加持久化在线编辑锁、小文本安全读取、审批保存与乐观冲突检测。它不代表 M2 或整个运维平台已经完成。

## 上传流程

1. 浏览器以 4 MiB 为单位增量读取文件并计算整文件 SHA-256，不把整个大文件一次性加载进内存。
2. 审批单精确绑定主机、目录、文件名、大小、SHA-256、分片大小和冲突策略。批准前不向服务端发送文件内容。
3. 批准后创建数据库上传会话并消费一次性审批票据，默认有效期为 24 小时。
4. 浏览器逐片计算 SHA-256，服务端校验摘要和精确偏移后，通过 SFTP 追加到目标目录中的随机临时文件。
5. 所有分片完成后，服务端重新流式读取远端临时文件并计算整文件 SHA-256。只有摘要与审批参数一致时才替换正式文件。
6. 浏览器在本地保存会话 UUID。网络或页面中断后，重新选择内容相同的文件会查询服务端偏移量并继续上传，不需要再次消费审批单。

OpenSSH SFTP 服务端优先使用 `posix-rename@openssh.com` 原子覆盖。服务端不支持该扩展时，系统先把旧目标改名为随机备份，再移动新文件；移动失败会恢复旧目标。权限错误或校验失败不会删除、截断或替换正式文件。

## 批量上传队列

批次在数据库中持久化，一次包含 1 至 50 个文件，总大小最多 5 TiB；服务端接受 1 至 4 路文件并发，当前前端固定为 2 路。浏览器先顺序计算每个本地文件的 SHA-256，再按 Unicode 文件名排序。一次性审批单精确绑定排序后的完整文件清单、主机、目录、分片大小、冲突策略和并发数，任何文件名、大小、摘要或并发数变化都不能消费原票据。

审批通过后，服务端在同一事务中创建批次和全部子上传会话。各子文件共享批次审批与关联 ID，但保留独立 UUID、顺序、偏移、摘要、临时路径和清理记录。浏览器最多同时推进两个文件，每个文件内部仍按偏移顺序传输，服务端只锁定正在写入的传输行，不会用批次行锁把不同文件串行化。

批次状态为 `active`、`paused`、`completed`、`failed` 或 `cancelled`：

- 暂停采用协作语义，已提交的当前分片允许完成，之后的分片和完成请求由服务端拒绝；恢复继续现有 `active` 子会话。
- 网络失败后前端先查询最新批次状态，并尽力把仍为 `active` 的任务切换为 `paused`；控制请求也失败时保留本地停止状态和批次 UUID，要求重新连接后核对。
- 当所有子文件完成时批次才是 `completed`；无活动文件且存在失败、过期或单独取消的子文件时批次转为 `failed`。
- 重试只重置失败文件。系统先通过 SFTP 删除失败的随机临时文件；权限或网络清理失败会保留失败状态、错误类型和尝试次数，不会从错误偏移继续。
- 取消把所有活动子文件标为 `cancelled`，远端临时文件由 Scheduler 的既有重试链路清理。已完成正式文件不会回滚。

浏览器本地存储只保存由主机、目录及完整文件清单摘要定位的批次 UUID，不保存文件内容。刷新后浏览器不能自行重新获得本地文件句柄；用户需要重新选择完全相同的文件集，前端校验服务端批次与全部文件元数据一致后才恢复。

## 在线文本编辑

文件列表中的普通文件可在 Ace 编辑器中打开。服务端只接受绝对路径、最大 2 MiB 的 UTF-8 文本，并拒绝 NUL 内容、目录和符号链接。创建会话时流式读取受限内容，保存文件大小、修改时间、ETag 和 SHA-256 作为基础版本。

同一主机和规范化路径只能有一个编辑者。锁默认 30 分钟过期，前端每 5 分钟续期；同一用户重新打开会复用当前会话 UUID，取消、卸载页面或切换主机时尽力释放。浏览器断线时仍由 Scheduler 处理锁过期和临时文件。

保存必须使用一次性审批单，审批参数精确绑定主机、路径、基础 ETag/SHA-256、新内容大小/SHA-256、编码和 `reject_on_change` 策略。服务端先重新检查正式文件；冲突时保持审批为未消费。通过后将内容写入同目录随机临时文件，重新校验远端 SHA-256，并保留原文件 POSIX mode、UID 和 GID；临时文件成功后再次检查基础版本，最后使用安全替换链路。任一写入、校验或元数据保留步骤失败都不会主动覆盖正式文件。

该流程是 SFTP 上的乐观并发控制，不是远端文件系统的强制锁。不遵守 Spug 编辑锁的外部程序仍可写入；SFTP 协议没有“比较版本并原子替换”操作，因此在最后一次检查与原子改名之间仍存在极短竞态窗口。

## API

接口位于 `/api/file/uploads/`、`/api/file/upload-batches/` 和 `/api/file/edit-sessions/`，并继续受 `host.console.upload` 页面权限、`file.read`/`file.write` 对象授权和统一审批门禁保护。会话只能由所有者访问，每次请求都重新校验主机权限。

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/api/file/uploads/` | POST | 创建上传会话并消费完全匹配的批准票据 |
| `/api/file/uploads/<uuid>/` | GET | 查询本人上传会话和服务端已确认偏移量 |
| `/api/file/uploads/<uuid>/` | DELETE | 取消会话并尽力清理远端临时文件 |
| `/api/file/uploads/<uuid>/chunk/` | POST | 上传一个带偏移和 SHA-256 的分片 |
| `/api/file/uploads/<uuid>/complete/` | POST | 校验远端整文件并安全替换目标文件 |
| `/api/file/upload-batches/` | GET | 查询本人最近的上传批次，可按主机过滤 |
| `/api/file/upload-batches/` | POST | 消费完全匹配的整批批准票据并创建全部子会话 |
| `/api/file/upload-batches/<uuid>/` | GET | 查询批次及全部子文件进度 |
| `/api/file/upload-batches/<uuid>/` | PATCH | 执行 `pause`、`resume` 或 `retry` |
| `/api/file/upload-batches/<uuid>/` | DELETE | 取消批次并把未完成临时文件交给清理任务 |
| `/api/file/edit-sessions/` | POST | 读取文本基础版本并取得独占编辑锁 |
| `/api/file/edit-sessions/<uuid>/` | GET | 查询本人编辑锁状态 |
| `/api/file/edit-sessions/<uuid>/` | PATCH | 执行 `heartbeat` 续期 |
| `/api/file/edit-sessions/<uuid>/` | DELETE | 取消编辑并清理临时文件 |
| `/api/file/edit-sessions/<uuid>/save/` | POST | 消费完全匹配的批准票据并安全保存 |

服务端允许 256 KiB 至 16 MiB 的分片，单个会话最大文件大小为 1 TiB。当前前端固定使用 4 MiB 分片和 `overwrite` 策略。

数据库迁移 `file.0001_initial` 新增 `file_transfers` 表，`file.0002_filetransfer_cleanup_fields` 增加清理状态和时间记录，`file.0003_filetransferbatch` 新增 `file_transfer_batches`、子文件顺序与批次外键，`file.0004_fileeditsession` 新增按主机和路径唯一的 `file_edit_sessions`。表中保存所有者、目标、审批关联、摘要、偏移、状态和过期时间，不保存文件内容或主机凭据。

## 断点下载

`GET /api/file/object/?id=<host>&file=<path>` 支持一个字节范围，包括 `bytes=start-end`、`bytes=start-` 和 `bytes=-suffix`。合法范围返回 `206 Partial Content`、精确的 `Content-Length` 和 `Content-Range`；越界、格式错误或多范围请求返回 `416 Requested Range Not Satisfiable`。HEAD 返回与 GET 相同的范围元数据，但不打开远端文件或传输正文。

响应同时提供 `Accept-Ranges: bytes`、强 `ETag`、`Last-Modified` 和 `If-Range` 语义。`If-Range` 与当前文件不匹配时忽略 Range 并返回完整 `200`，防止把两个版本的文件拼接在一起。服务端按限定长度流式读取 SFTP 文件并发送 `X-Accel-Buffering: no`，不会为了范围下载把远端整文件载入内存。

当前前端仍使用浏览器下载链接，并提示服务端具备 HTTP Range 能力。文件表格可多选并一次发起多个独立下载，浏览器可能要求用户允许站点下载多个文件；它不是服务端 ZIP 打包，也没有隐藏的后台下载队列。浏览器是否自动恢复取决于浏览器和网络环境；需要可控重试时应使用支持 Range 的下载工具。

## 临时文件清理

上传会话记录 `pending`、`removed`、`missing` 或 `failed` 清理状态，以及尝试次数、最近尝试时间、完成时间和脱敏错误类型。完成上传后临时路径随安全替换消失并直接标记为已清理；用户取消上传时同步尝试删除临时文件。

Scheduler 每 15 分钟扫描以下会话，每轮最多处理 100 条，并以数据库行锁避免同一会话并发清理：

- 已超过 24 小时有效期的 `active` 会话；
- `expired`、`failed` 或 `cancelled` 且仍待清理或上次清理失败的会话；
- 每个会话最多尝试 10 次，权限或网络失败保留为 `failed` 供后续重试，文件确实不存在记录为 `missing`。

同一 Scheduler 任务还扫描已超过 30 分钟的活动编辑锁，以及已过期或已取消但仍待清理的编辑会话；同样每轮最多 100 条、单会话最多尝试 10 次。

管理命令默认只报告候选项，不连接 SFTP。必须显式传入 `--execute` 才会删除：

```bash
python3 manage.py cleanup_file_transfers
python3 manage.py cleanup_file_transfers --execute
```

## 安全与失败语义

- 会话 UUID 不等同于授权；每次查询和分片请求都会重新校验登录用户、会话所有者及主机对象权限。
- 只接受当前服务端偏移对应的完整分片，重复或乱序请求失败关闭，避免并发覆盖。
- 若进程在远端分片落盘后、数据库偏移提交前中断，下一次分片会以随机临时文件的实际长度恢复偏移；最终整文件摘要仍必须匹配审批值。
- 每片先校验再写入，整文件在远端再次校验；摘要不匹配时会话标记为失败，正式文件保持不变。
- 上传网络错误保持会话为 `active`，用户可重试；已完成调用具备状态级幂等响应，不会重复产生成功事件。
- 审计链记录上传会话和批次的开始、控制、成功、取消及最终失败，也记录下载开始、完成或客户端中断，以及每次临时文件清理结果；事件包含关联 ID 和必要文件元数据，不包含文件内容或原始连接错误。
- 编辑审计记录会话开始、保存成功/失败、取消和 Scheduler 清理；只记录路径、大小和摘要，不写入文件内容。

## 当前限制

- Range 下载当前只支持单文件的一个字节范围；批量下载是浏览器发起多个单文件请求，尚未实现服务端打包、前端可恢复下载任务管理器、全局并发与带宽策略。
- 批量上传并发由浏览器执行，不是脱离浏览器的后台 Worker；页面关闭后必须重新选择完全相同的本地文件才能恢复。
- 前端尚未提供 `reject`/`overwrite` 冲突策略选择和重命名策略。
- 在线编辑暂只支持不超过 2 MiB 的 UTF-8 普通文件，没有其他编码、差异预览、版本历史、合并或回滚界面。
- 安全替换保留 POSIX mode、UID 和 GID，但 SFTP 无法通用保留 ACL、扩展属性或自定义 SELinux 上下文；这类文件不应使用当前在线编辑。
- 外部程序不会被 Spug 锁阻止；最后冲突检查与远端改名之间的极短竞态窗口受 SFTP 协议限制无法完全消除。
- 断点记录依赖浏览器本地存储；本地存储不可用时，同一页面内可继续，但刷新后的自动发现能力受限。
