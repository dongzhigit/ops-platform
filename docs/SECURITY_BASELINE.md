# M0 安全验证基线

验证日期：2026-08-18

## 当前结论

M0 过渡镜像已经可以重复构建，但尚不满足正式生产发布条件。它可用于隔离内网中的兼容性验证，不应直接暴露到公网。

Trivy 0.65.0 对 `spug-ops:0.1.0-alpha.8` 的严重和高危漏洞复扫结果如下。数量是漏洞在软件包中的出现次数，并非去重后的 CVE 数量；漏洞库更新后数字可能变化。“有修复版本”指 Trivy 状态为 `fixed` 且给出了修复版本的项目。

| 层级 | 严重 | 高危 | 有修复版本 |
| --- | ---: | ---: | ---: |
| CentOS 7.9.2009 | 0 | 155 | 46 |
| Python 依赖 | 3 | 48 | 51 |
| 合计 | 3 | 203 | 97 |

Dockerfile 纳入 CentOS 7 最终安全更新后，操作系统层严重漏洞降为 0。`0.1.0-alpha.8` 最终镜像因保留 Git 等发布流程必需工具，操作系统层为 155 个高危；CentOS 7 已停止安全维护，扫描器也明确提示检测结果可能不完整，因此这些更新只是过渡措施。漏洞库更新会导致统计数字和可修复判定变化，本表使用 Trivy 0.65.0 在 2026-08-18 下载的最新数据库复扫。

尚存的严重项：

| --- | --- | --- | --- |

- MariaDB 10.11 全量测试：69 项通过，包含在线编辑所有权、独占锁/心跳、UTF-8 与大小边界、审批参数防篡改、远端冲突、安全替换、过期/取消清理、Scheduler 编排和符号链接拒绝场景。
- 真实 OpenSSH SFTP 集成测试通过：除两文件并发分片、暂停恢复、损坏重试和取消清理外，还验证了 UTF-8 文件在线读取、审批保存、远端 SHA-256 以及 POSIX mode/UID/GID 保留。
- React 生产构建通过；安全中心审批/审计页面、批量命令、文件分发、SSH 单文件/整批分片上传、批次进度与控制、多选下载、Range 提示、在线编辑弹窗/心跳/审批保存和计划任务审批门禁均已纳入最终镜像构建产物。
- 全量 Django 迁移基线可在 MariaDB 空库安装到 `file.0004`，模型漂移检查通过；从带既有上传记录的 `file.0003` 升级到 `file.0004` 后，原会话 UUID、偏移和状态保持不变，编辑锁唯一约束与索引正常。
- Python 源码编译检查通过。
- Docker Compose 配置解析通过。
- `linux/amd64` alpha.8 镜像完整构建通过，OCI 版本标签和应用版本均为 `0.1.0-alpha.8`，镜像包含当前仓库后端和镜像构建阶段重新编译的前端。
- alpha.8 镜像在 MariaDB 启动并自动迁移到 `file.0004`；Nginx、API、WebSocket、Worker、Scheduler 和 Monitor 全部运行，Nginx 代理后的在线编辑接口完成未登录 401 和已登录业务层 200 路由验证，构建产物包含编辑 API 客户端。
- 镜像内 Django、Channels、Paramiko、MySQL 和 LDAP 依赖导入通过。
- Shell 语法和 Git 差异检查通过。
- Gitleaks 全仓库扫描未发现泄露。

## 正式发布门禁

- 严重漏洞必须为 0。
- 有可用修复版本的高危漏洞必须修复；不能立即修复的项目需要有负责人、影响分析、隔离措施和到期时间。
- 基础镜像、Python 和 Django 必须处于官方安全支持周期。
- 依赖版本必须锁定，镜像必须在 CI 中重新构建和扫描。
- 数据库备份恢复、迁移回滚、Linux FUSE 文件分发和 TLS 反向代理必须在目标环境完成演练。

复扫示例：

```bash
trivy image --scanners vuln --severity CRITICAL,HIGH spug-ops:0.1.0-alpha.8
```
